# Demo Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an environment-gated, interactive frontend demo workspace without live mail services.

**Architecture:** A demo adapter implements the existing API transport boundary in memory, so React components and Zustand retain their production interfaces. App bootstrap bypasses server authentication only when the build flag is true.

**Tech Stack:** React 19, Zustand, Vite, Node test runner, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-16-demo-mode-design.md`

## Global Constraints

- Enable demo only with `VITE_DEMO_MODE=true`; production defaults to disabled.
- Demo code must never perform a fetch to `/api`.
- Keep the current `api` interface stable for all existing components.
- Demo mail changes are intentionally in-memory only.

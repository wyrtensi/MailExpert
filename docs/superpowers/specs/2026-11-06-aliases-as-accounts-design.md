# Алиасы как ящики (Display aliases as accounts)

Дата: 2026-11-06. Статус: согласовано владельцем 2026-11-06.

## Зачем

Ящик `team@example.com` собирает почту 23 клиентских алиасов, `science@` - 26, `post@` - 30. Сотрудник
открывает панель, чтобы ответить конкретному клиенту, а его письма перемешаны с письмами остальных 22.
Плашка получателя в списке писем (v1.1.0) помогает различать, но не отфильтровывает.

Цель: сотрудник одним переключателем показывает каждый алиас как отдельный ящик в боковом списке и
работает с клиентом как с отдельной почтой: его входящие, его отправленные, ответ с его адреса.

## Решения владельца

- Переключатель - отдельной строкой в шапке бокового списка, под "Все входящие". Подпись
  "Алиасы как ящики" / "Display aliases as accounts". Переключается сразу, без перезагрузки.
- Каждый сотрудник включает режим для себя. Состояние хранится в пользователе на сервере, не в
  localStorage: на другом компьютере и в другом браузере у того же пользователя режим тот же.
- Сам ящик-владелец (`team@` и т.д.) остаётся в списке как сейчас, со всей почтой.
- Алиасы показываются строками того же уровня, что и ящики (вариант B), не вложенными в ящик.
- Строка алиаса выглядит как строка обычного ящика: имя первой строкой, адрес второй. Например
  `Name Surname` / `name_surname@example.com`. Без пометки, через какой ящик он работает.
- В ящике алиаса во "Входящих" - только письма, пришедшие на этот алиас. В его раскрывающемся меню
  "Отправленные" - только письма, отправленные с этого адреса.

Макет, который владелец видел (последний вариант): ящики сверху как сейчас, ниже алиасы по алфавиту,
у выбранного алиаса раскрыты "Входящие" и "Отправленные", справа число непрочитанных.

## Догадки, которые владелец видел и не поправил

- Справа у строки алиаса - число непрочитанных в его "Входящих".
- У алиаса только две папки: "Входящие" и "Отправленные". Спама, корзины, черновиков и меток нет.
- Удалённые алиасы (те, что в списке писем с серой плашкой) строк не получают.
- "Написать" и "Ответить" из ящика алиаса ставят в "От" этот алиас.
- "Все входящие" не меняются, письма не дублируются.
- Режим работает для любого ящика с алиасами, не только для team@.

## Что уже есть в коде (main @ 7d79dcd0, v1.1.1)

- Пользовательские настройки: `users.preferences JSONB` (`backend/migrations/0001_baseline.sql`),
  `GET/PATCH /api/auth/preferences` (`backend/src/routes/auth.js`, `getPreferences`/`patchPreferences`,
  ключи по белому списку). Ближайший образец булевой настройки - `sortAccountsByLatest`, на фронтенде
  `store/index.js` (`loadPreferences`, `schedulePrefSave`). Пользователи разные и в `AUTH_MODE=local`
  (у каждого свой логин), ящики общие для всех.
- Боковой список: `frontend/src/components/Sidebar.jsx` ("Все входящие" и цикл по `visibleAccounts`),
  выбор - `setSelectedAccount(accountId, folder)` в `store/index.js`.
- Список писем: `GET /api/mail/messages` -> `listMessages` (`backend/src/services/messageService.js`),
  общий `whereConditions` для обычного и тредового вида. Счётчик total в обычном пути берётся из
  `folders.total_count`, при фильтре его надо считать по строкам (как уже делает путь с `category`).
- Непрочитанные: `GET /api/mail/unread-counts` отдаёт снимки IMAP по INBOX (`folders.server_unread_count`).
  Для алиаса нужен подсчёт по базе.
- Плашка получателя и выбор "От" при ответе: `frontend/src/utils/replyAlias.js` (`pickReplyAlias`),
  `frontend/src/utils/mailboxBanner.js` (`recipientAliasFor`). Порядок: `delivery_addresses`, потом
  To/Cc. Сейчас только на фронтенде.
- Индексы: GIN `idx_messages_recipient_addresses` по `message_recipient_addresses(to, cc)` (0071),
  `idx_messages_account_from_date` по `(account_id, lower(from_email), date)` (0068). На
  `delivery_addresses` индекса нет; у писем до миграции 0037 поле пустое, пока ящик не пересинхронизирован.
- Сортировка алиасов: `frontend/src/utils/aliasSort.js` (`sortAliasesByName`).

## Что делаем

### 1. Настройка пользователя

Булев ключ в `users.preferences` (имя на усмотрение исполнителя), по умолчанию выключено. Пишется через
`PATCH /api/auth/preferences` по образцу `sortAccountsByLatest`. Зеркало в localStorage допустимо только
для первой отрисовки, источник истины - сервер.

### 2. Боковой список

- Строка-переключатель под "Все входящие".
- При включённом режиме после ящиков (в их обычном порядке) идут алиасы всех ящиков, по алфавиту по
  правилу `sortAliasesByName`, вперемешку между ящиками.
- Какие алиасы получают строку: текущие алиасы ящика, на которые панель умеет отвечать, то есть ровно
  те, что участвуют в выборе плашки и "От" (`pickReplyAlias`). Алиас с адресом самого ящика строки не
  получает. Ящик выключен или скрыт - его алиасов тоже нет.
- Строка алиаса раскрывается в "Входящие" и "Отправленные", как ящик раскрывается в папки.
- Алиас удалили (синк Gmail), пока он выбран - выбор переходит на ящик-владелец.

### 3. Письма в ящике алиаса

- "Входящие" алиаса - письма из INBOX ящика-владельца, получатель которых - этот алиас. Правило отбора
  то же, по которому строится плашка: письмо, у которого в ящике-владельце плашка "на X", обязано быть
  во "Входящих" алиаса X, и наоборот. Значит, письмо попадает во "Входящие" ровно одного алиаса - того,
  кого выбирает плашка (`recipientAliasFor` -> `matchReplyAlias`: сначала `delivery_addresses`, потом
  один проход To/Cc/From по алиасам в их порядке; эталон - код, а не этот пересказ). Серверный отбор повторяет это правило, а не "алиас есть хоть где-то в адресах".
  Решение руководителя: письма сразу на два алиаса редки, совпадение с плашкой важнее.
- "Отправленные" алиаса - письма из папки отправленных ящика-владельца, у которых From = адрес алиаса.
- Фильтр работает на сервере (пагинация, счётчики, тредовый вид, "только непрочитанные"), а не
  фильтрацией загруженной страницы на клиенте.
- Вкладок категорий (основные, рассылки, промо...) во "Входящих" алиаса нет: показываются письма всех
  категорий. Иначе письмо-рассылка с плашкой "на X" пропало бы из ящика X, а счётчик разошёлся бы со
  списком. Решение руководителя.
- Действия над письмом в ящике алиаса (прочитать, архив, удалить, переместить, метки) - это действия
  над тем же письмом ящика-владельца, как сейчас.
- Число непрочитанных у строки алиаса - по его "Входящим", обновляется по тем же событиям, что у ящиков.

### 4. Отправка

"Написать" и "Ответить" из ящика алиаса ставят в "От" этот алиас. Он же совпадает с плашкой письма,
потому что письмо попадает только к тому алиасу, кого выбирает плашка.

### 5. Документация, переводы, демо

- Руководство пользователя (раздел про алиасы) - по-русски.
- Строки интерфейса - в `locales/en.json` и `ru.json`.
- Новые параметры API - в `frontend/src/demo/`.

## Не делаем

- Изменения "Все входящие" и ящиков-владельцев.
- Отдельные папки алиаса кроме "Входящих" и "Отправленных", отдельный поиск по алиасу.
- Права доступа по алиасам.
- Письма, где алиас был только в Bcc и нет `delivery_addresses`: во "Входящие" алиаса не попадают
  (то же ограничение, что у плашки).
- Отправленные письма с неполным IMAP-конвертом, у которых парсер подставил в From адрес ящика
  (`enrichParsedMetadata` в `backend/src/services/messageParser.js`): в "Отправленные" алиаса не
  попадают, запасного разбора сырых заголовков не делаем. Известное ограничение, решение руководителя;
  письма, отправленные из панели, From алиаса получают.

## Провал, даже если технически работает

- В ящике-владельце у письма плашка "на X", а во "Входящих" алиаса X его нет (или наоборот).
- "Входящие" алиаса у большого ящика (`team@` - старый аккаунт) открываются заметно дольше, чем
  "Входящие" самого ящика.
- Режим сбросился после перезагрузки или на другом компьютере того же пользователя.
- Ответ из ящика алиаса ушёл с `team@example.com`.
- Число непрочитанных у алиаса не совпадает с тем, что видно в его "Входящих".
